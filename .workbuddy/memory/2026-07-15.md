# 2026-07-15

## 提高测试用例生成的 token 缓存命中率

排查确认：之前 `build_chat_model` 从未设置 `enable_prompt_cache`，全链路没有开启 prompt caching，命中率近乎 0。

### 改动
- `backend/utils/llm_factory.py`：新增 `prompt_cache: Optional[bool]=None` 参数；None 时按 `base_url` 主机名自动判定（含 "deepseek" 则开启），并新增 `_is_deepseek_host()`。开启时向 `extra_body` 注入 `enable_prompt_cache: True`（与 thinking 标记合并）。
- `backend/config.py`：新增 `prompt_cache_enabled`（默认 None=自动）；`ConfigManager.get_prompt_cache_enabled()` 供 config 开关强制开/关。
- `backend/utils/model_utils.py`：`generate_testcases` 读取 config 并透传到 3 处 `build_chat_model` + `create_testcase_agent`；agent 路径工具列表按 `t.name` 排序（稳定前缀）；fallback 原始 API 调用复用 `model.extra_body`。
- `backend/utils/helpers.py`：`_TokenUsageCallback.on_llm_end` 解析 usage 的 `prompt_cache_hit_tokens`/`prompt_cache_creation_tokens`（兼容 Anthropic 命名），打印 `[缓存命中]` 日志与命中率。

### 验证
- `tests/test_llm_factory.py` 新增 4 个缓存用例（自动开/关、强制开/关），全部通过；全量 `tests/` 127 passed。
- 日志中观察 `[缓存命中]` 字段即可验证：连续同类型请求系统提示词前缀（~4000 token）应命中缓存。

### 备注
- DeepSeek prompt caching 前缀需 ≥1024 token 且 TTL 较短，跨长间隔仍会 miss，属正常。
- 不兼容网关可经 config `prompt_cache_enabled: false` 关闭，避免 extra_body 报错。

## 测试点「设计方法」编辑字段回显为汉字

`frontend/src/components/test-case/RequirementTestPointManager.tsx` 编辑弹窗中原「设计方法」为自由文本 `Input`（需手输英文 code）。改为 `Select`：value 存 code，label 显汉字，选项来自已有 `DESIGN_METHOD_LABEL`（场景法/等价类划分/边界值分析/错误推测法/判定表法/正交试验法/状态迁移法/因果图法）。新增/未知 code 时回退为原值选项，避免数据丢失。已 `tsc --noEmit` 通过，无类型错误。
