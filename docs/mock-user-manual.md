# Mock 功能用户手册

通过 Mock 功能，无需后端开发完成即可拿到"像真数据"的接口响应：导入接口文档 → 打开开关 → 直接调用。也可作为代理拦截浏览器/App 的真实请求。

## 第 1 步：导入接口文档

进入「接口测试」页面，左侧填写 OpenAPI URL（支持 swagger-config 地址，自动解析全部分组文档）或上传 Swagger 文件，点击「导入接口文档」。

## 第 2 步：开启项目 Mock

选中接口项目，在项目设置中打开「Mock 服务」开关，并确认 Mock 前缀。前缀需带 service 段，格式为 `/service/{服务名}`（如合同服务为 `/service/contract`）。开启后页面会显示调用地址：

```
http://<平台地址>/api/mock/service/contract/users/123
```

- 响应按各接口的**响应 Schema 实时生成**，每次请求返回不同随机值
- 时间字段自动返回**毫秒时间戳**；description 里写了「1奖励 2处罚」这类说明的字段，只会返回说明中的值
- 请求里传 `pageSize`，返回数组就按该条数输出；请求与响应的同名字段自动回填

## 第 3 步：（可选）拦截真实流量

如果希望前端联调时**不改任何代码**就把真实请求换成 Mock 数据：

1. 点屏幕右侧「Mock 代理」浮动按钮，启动代理（默认端口 9000）
2. 点击「下载CA证书」，双击安装到操作系统的**受信任的根证书颁发机构**（HTTPS 拦截必需）
3. 让流量走代理：
   - 浏览器：安装 **SwitchyOmega** 插件，新建情景模式，代理服务器填 `<平台IP>:9000`，需要时切换
   - 手机 App：WiFi 手动代理指向 `<平台IP>:9000`

## 第 4 步：让平台里配好的 Mock 被代理命中

Mock 接口平台里配置的 Mock（手写 Mock 与项目级 Schema Mock）会自动参与代理匹配。有两种方式指定"哪个真实接口该用这条 Mock"：

### 方式 A（推荐）：直接填真实接口地址

在「Mock 接口平台」新建/编辑 Mock 时，填写「代理拦截地址」，例如：

```
http://192.168.13.178:18896/contract/update
```

配好后，代理下次监听到这个接口的真实调用时，就直接返回这条 Mock 的响应——**不需要再建转发规则**。支持以下写法：

| 写法 | 示例 |
|------|------|
| 完整 URL | `http://192.168.13.178:18896/contract/update` |
| 省略协议 | `192.168.13.178:18896/contract/update` |
| 主机 + 路径 | `192.168.13.178/contract/update` |
| 仅路径（对所有拦截主机生效） | `/contract/update` |

路径里可用 `{param}` 占位，如 `/contract/detail/{id}` 能匹配 `/contract/detail/88`，且 `{id}` 会回填到响应体。端口与 query 参数不参与匹配。

### 方式 B：用转发规则圈定范围

在 Mock 代理窗口的「转发规则」中点「新建规则」，圈定哪些主机的哪些请求被拦截：

| 字段 | 示例 | 说明 |
|------|------|------|
| 主机模式 | `192.168.13.178` 或 `*.example.com` | 精确 IP/域名；`*.` 通配任意子域 |
| 服务前缀 | `/contract` 或 `/service/contract` | 真实流量去掉该前缀后，才按平台里的相对路径匹配；留空=不剥离 |
| 路径模式 | `/contract/` 或留空 | 尾斜杠表示该目录下全部接口；`{param}` 匹配单段；留空匹配全部 |

**服务前缀是最容易配错的一项**。平台里的 Mock 存的是服务内相对路径（如 `/update`、`/token/get`），而真实流量通常带服务前缀：

| 真实调用 | 服务前缀 | 剥离后 | 平台 Mock 路径 |
|----------|----------|--------|----------------|
| `/contract/update` | `/contract` | `/update` | `/update` |
| `/service/contract/token/get` | `/service/contract` | `/token/get` | `/token/get` |

> 存量规则升级后会自动按原路径模式回填服务前缀（如 `/contract/` → `/contract`），一般无需手工修改。

命中规则的请求返回 Mock 数据，未命中的自动透传到真实服务，不影响其他上网行为。HTTPS 只对命中规则的主机做解密拦截。

## 第 5 步：确认配置是否生效

Mock 代理窗口的「接口平台 Mock」页签会列出所有启用的 Mock，并标注每条是否**已覆盖**（会被代理命中）：

- 显示「已覆盖」：该 Mock 要么配置了代理拦截地址，要么落在某条转发规则的主机+路径范围内
- 显示「无规则覆盖」：代理永远不会命中它，需要配置代理拦截地址或补一条转发规则

同一页签内的「命中预览」可以输入主机 + 方法 + 路径，直接看到这个请求**会不会被拦截、会命中哪条 Mock、返回什么响应**——预览不会写入流量日志，适合反复调试。典型用法：想确认 `192.168.13.178` 上的 `POST /contract/update` 会返回哪条 Mock，填进去点预览即可。

## 第 6 步：验证与关闭

- 在 Mock 代理窗口的「流量日志」页查看每次请求：`代理→Mock` 表示已拦截返回假数据，`透传` 表示走了真实服务，点「详情」可看完整请求/响应。一次命中只记一条日志。
- 项目参数校验失败时返回 400，错误原因写在响应体里
- 若某条 Mock 解析出错，代理会记录一条 `代理错误` 日志并**继续透传真实服务**，不会让请求直接失败
- 联调结束：关闭项目的「Mock 服务」开关、清空代理拦截地址、停用规则或停止代理即可恢复真实环境

## 常见问题

**Q：配了 Mock 但代理没拦住？**
先看「接口平台 Mock」页签的覆盖状态。常见原因是没配代理拦截地址、且没有规则覆盖该主机；或者规则的服务前缀写错，导致剥离后的路径与 Mock 路径对不上。

**Q：同一路径在不同环境有多条 Mock，会串吗？**
给 Mock 填「定向主机」（如 `192.168.13.178` 与 `*.sg.luban.cn`）即可区分；定向主机的 Mock 优先于通用 Mock。

**Q：只想临时验证，不想产生日志？**
用「命中预览」，它不会写流量日志。
